# SentinelSuite

SentinelSuite is the unified frontend composition layer for the three existing cybersecurity projects in this workspace. It preserves the original services and presents them through one operational UI.

## Existing services

| Module | Existing implementation | Default URL |
| --- | --- | --- |
| Ransomware Analysis | `AI-Malware-Analysis-Platform` FastAPI service | `http://127.0.0.1:8080` |
| Phishing Link Analysis | `phishing_react_app_fixed/backend` FastAPI service | `http://127.0.0.1:8000` |
| Intrusion Detection | `SentinelIDS_Project_Vidisha/SentinelIDS` FastAPI service | `http://127.0.0.1:8002` |

The new frontend calls the original contracts directly. It does not duplicate models, analysis pipelines, file handling, report generation, or IDS processing.

## Run locally

For the complete local stack, use the orchestration script. It stops existing
SentinelSuite API/frontend processes, restarts CAPE, deletes only CAPE tasks in
pending/queued/submitted states, removes old `memory.dmp` files from
`CAPE_STORAGE`, and then starts the ransomware, phishing, IDS, and frontend
services:

```bash
sudo ./super-start.sh
```

Set `CAPE_STORAGE` if CAPE uses a non-default analysis directory. Do not run
this command while a CAPE task you want to keep is pending; pending tasks and
previous memory dumps are intentionally removed.

For development when CAPE is already running, use:

```bash
./start.sh
```

This stops and restarts the existing SentinelSuite application processes but
does not restart CAPE or delete CAPE data.

Start each service from its original project root:

```bash
# Terminal 1
cd "AI-Malware-Analysis-Platform"
pip install -e .
malware-api

# Terminal 2
cd "phishing_react_app_fixed/backend"
pip install -r requirements.txt
python main.py

# Terminal 3
cd "SentinelIDS_Project_Vidisha/SentinelIDS"
pip install -r requirements.txt
# Set IDS_INTERFACE to the capture interface when needed. Critical alerts
# launch one bounded internal Nmap follow-up scan by default.
export IDS_ACTIVE_SCAN_ENABLED=1
uvicorn api.app:app --reload --port 8002

# Terminal 4
cd SentinelSuite/frontend
cp .env.example .env
npm install
npm run dev
```

Open `http://127.0.0.1:3000`.

## API mapping

- Ransomware: `GET /api/v1/health`, `POST /api/v1/analyze`, `GET /api/v1/jobs`, `GET /api/v1/jobs/{job_id}`, `GET /api/v1/reports`
- Phishing: `GET /api/health`, `GET /api/model-info`, `POST /api/scan`, `POST /api/report`
- IDS: `GET /health`, `GET /dashboard/summary`, `GET /dashboard/recent-alerts`, `GET /alerts`, `GET /scans`, `GET /reports`

See the source services for their complete request and response schemas. The frontend displays an actionable unavailable-service state when a backend is stopped.

## Architecture decisions

- The three existing backends remain separate processes and retain their original models and storage.
- `SentinelSuite/frontend` is the only user-facing frontend.
- Service URLs are environment variables; no keys or secrets are included in the client.
- A unified persistence layer was not introduced because the source projects use different storage contracts: malware filesystem reports and in-memory jobs, phishing request-time results, and IDS JSONL/report stores.
- Cross-service totals in the dashboard are explicitly operational aggregates, not a replacement for module-specific reports.

## IDS live alert behavior

- Live packet capture writes alerts to timestamped files under `SentinelIDS/data/alerts`.
- The dashboard reads those files through `/dashboard/recent-alerts`, so alerts generated by the capture process appear in the unified frontend.
- Risk severity is normalized as LOW (`0-29`), MEDIUM (`30-69`), or HIGH (`70-100`). HIGH alerts trigger one background Nmap follow-up per internal target.
- Set `IDS_ACTIVE_SCAN_ENABLED=0` to disable active follow-up scans while keeping detection and alert persistence enabled.

The phishing service currently supports API keys in its request schema; the unified UI does not send them, so server-side environment configuration should be preferred before internet-facing deployment.
